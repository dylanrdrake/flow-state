Core Concepts

The Scope

Every FlowState source instance is scoped to a DOM node — a light DOM HTMLElement. The root defines the scope: only elements that are DOM descendants of the root can receive state from that source instance.

Always mount a FlowState source on a host element, not a ShadowRoot. Scope traversal walks the light DOM via parentElement. If FlowState were mounted on a ShadowRoot it would be invisible to that traversal. To extend a scope into a shadow, use flowThrough(shadowRoot) after mounting on the host. 
<my-app>          ← FlowState root
  <child-a>       ← inside scope, can watch/get
  <child-b>
    <grandchild>  ← also inside scope

When a child calls flowWatch() or flowGet(), it dispatches a CustomEvent that bubbles up the DOM. The first ancestor that owns that key intercepts it. Scopes nest naturally — a child component can shadow a key from a parent without affecting siblings.

FlowState enforces and encourages one-way data flow: state updates flow down through the DOM from parents to children. Only the owner of a FlowState source instance can call source.update(). If children need to request parent updates, expose actions (plain functions as source config values) on the parent and have children call those actions via flowGet().

See the above visualization in action and code!

State is Immutable Between Updates

FlowState deep-freezes its internal values after every update. You cannot mutate state in place. All changes go through source.update().

Updates are Batched

Multiple source.update() calls in the same synchronous turn are batched into a single flush via queueMicrotask. Watchers and bindings are only notified once after the flush. 

source.update({ count: 1 });
source.update({ name: 'Alice' }); // batched — one notification fires

source.update() returns a Promise that resolves after the flush completes, so you can await it when you need to read the post-update value immediately.

Watchers fire immediately

When you register a watcher with flowWatch(), it calls your callback immediately with the current value.

Ways to Use FlowState

1. Manually

Mount a FlowSource on any DOM element. Use declarative HTML bindings and source.update() in your scripts — no custom elements required.

<!-- HTML -->
<div id="app">
  <span flow-watch-count-to-prop="textContent">0</span>
  <button id="inc">Increment</button>
</div>
import { FlowSource } from 'flow-state';

const source = new FlowSource(document.getElementById('app'), {
  count: 0,
});

document.getElementById('inc').addEventListener('click', () => {
  source.update(prev => ({ count: prev.count + 1 }));
});

2. Manually with Web Components

For plain HTMLElement classes where you manage everything manually.

import { FlowSource, flowWatch, flowThrough } from 'flow-state';

class MyCounter extends HTMLElement {
  #source;
  #countUnsub = () => {};

  connectedCallback() {
    const shadow = this.attachShadow({ mode: 'open' });

    // ⚠️ Create FlowSource BEFORE appending children.
    this.#source = new FlowSource(this, {
      count: 0,
    });
    // Register the shadow so declarative bindings inside it receive updates.
    flowThrough(shadow);

    shadow.innerHTML = `<button id="btn">Click me</button>`;

    this.#countUnsub = flowWatch(this, 'count', n => {
      shadow.getElementById('btn').textContent = `Clicked ${n} times`;
    });

    shadow.getElementById('btn').addEventListener('click', () => {
      this.#source.update(prev => ({ count: prev.count + 1 }));
    });
  }

  disconnectedCallback() {
    // Remove the watcher on the parent source when this element leaves the DOM.
    // destroy() only cleans up this element's own FlowSource.
    this.#countUnsub();
    this.#source?.destroy();
  }
customElements.define('my-counter', MyCounter);

flowWatch() returns an unsubscribe function. Store it when you create the watcher in a component, then call it in disconnectedCallback() so the parent source stops tracking that watcher when the element is removed. source.destroy() only cleans up the component's own FlowState source; it does not remove watchers registered on an ancestor source.

Use new FlowSource(root, config) to create a scope.

3. Component — FlowStateComponent

A base class that handles shadow DOM creation, styles, template stamping, and FlowState initialization in the correct order automatically. 

import { FlowStateComponent, flowWatch } from 'flow-state';

class MyCounter extends FlowStateComponent {
  shadowMode = 'open';
  styles = CSS`button { font-size: 1.5rem; }`;
  template = HTML`<button id="btn">Click 0 times</button>`;

  source = {
    count: 0,
  };

  connectedCallback() {
    super.connectedCallback(); // always call first

    flowWatch(this, 'count', n => {
      this.shadowRoot.getElementById('btn').textContent = `Clicked ${n} times`;
    });

    this.shadowRoot.getElementById('btn').addEventListener('click', () => {
      this.source.update(prev => ({ count: prev.count + 1 }));
    });
  }

  // ⚠️ Not necessary unless you need custom cleanup,
  // because FlowStateComponent auto-cleans owned watchers
  // and destroys its own source scope in disconnectedCallback().
  //If you do override it, call super.disconnectedCallback().
  disconnectedCallback() {
    super.disconnectedCallback();
    // Any component specific cleanup can go here as well.
  }
}
customElements.define('my-counter', MyCounter);

FlowStateComponent exposes this.source — the source instance API returned by the FlowState constructor.

Auto-cleanup: FlowStateComponent tracks flowWatch() subscriptions created from the component host and its own ShadowRoot, unsubscribes them, and destroys its own FlowState scope in disconnectedCallback(). If you override disconnectedCallback(), call super.disconnectedCallback().

Light DOM mode: omit shadowMode entirely to render the template into the element itself (no shadow root). Use this.querySelector() instead of this.shadowRoot.getElementById(). 

class MyBanner extends FlowStateComponent {
  // no shadowMode — renders into light DOM
  template = `<p id="msg"></p>`;
  source = { message: 'Hello' };
  connectedCallback() {
    super.connectedCallback();
    flowWatch(this, 'message', v => {
      this.querySelector('#msg').textContent = v;
    });
  }
}
Cleanup warning: FlowStateComponent already cleans up owned watchers and destroys its own source scope in disconnectedCallback(). If you override it, call super.disconnectedCallback().

disconnectedCallback() { super.disconnectedCallback(); }
Reference

The Source Config Object

{
  // Plain values — any JSON-serializable type
  count: 0,
  user: { name: 'Alice', role: 'admin' },
  items: [],

  // Computed values — wrap with flowCompute(fn, deps)
  // fn receives the listed deps as positional arguments
  fullLabel: flowCompute((user) => `${user.name} (${user.role})`, ['user']),

  // Top-level functions are actions — non-reactive, accessible via flowGet()
  doSomething: (arg) => console.log(arg),
}

Computed Values

Computed values use flowCompute(fn, deps). The function receives each listed dependency as a positional argument and is re-evaluated lazily when any dependency changes. Dependencies can reference plain state keys or other computed keys. 

price: 10,
qty: 3,
taxRate: 0.1,

subtotal: flowCompute((price, qty) => price * qty, ['price', 'qty']),

// Depends on another computed key (subtotal)
total: flowCompute((subtotal, taxRate) => subtotal * (1 + taxRate), ['subtotal', 'taxRate']),

FlowState resolves computed dependencies in order (upstream first). Circular dependency chains are rejected with an explicit error.

Source Instance API

The object returned by new FlowSource(…), also accessible as this.source in FlowStateComponent.

source.update(patch | fn)

Update state. Accepts either a partial object or a function that receives the current state and returns a partial object. Returns a Promise that resolves after the microtask flush. 

// Partial object
source.update({ count: 5 });

// Function (safe for values that depend on current state)
source.update(prev => ({ count: prev.count + 1 }));

// Deep partial — merges into nested objects
source.update({ user: { name: 'Bob' } }); // only name changes, role preserved

// Awaitable
await source.update({ count: 99 });
const current = flowGet(root, 'count'); // 99 ✓
⚠️ Only configured keys can be updated. Attempts to add new keys are silently ignored (with a console warning). Computed keys cannot be updated. This is a design decision.

source.destroy()

Destroy the source instance when a component is permanently removed. 

disconnectedCallback() {
  this.source?.destroy();
}

For FlowStateComponent, this is automatic. If you override disconnectedCallback(), call super.disconnectedCallback(). 

class TaskPanel extends FlowStateComponent {
  disconnectedCallback() {
    super.disconnectedCallback();
  }
}

Functional helpers like flowWatch, flowGet, and flowThrough are documented in the next section.

Functional Helpers

Used by child elements to reach a parent's FlowState without holding a direct reference. Everything works via DOM events that bubble up.

flowCompute(fn, deps)

Creates a computed value descriptor for use in a config object. fn receives each key listed in deps as a positional argument and is re-evaluated lazily when any dependency changes. Computed values are read-only and can depend on other computed values. 

total: flowCompute((price, qty) => price * qty, ['price', 'qty']),

// Can depend on another computed value
discounted: flowCompute((total, discount) => total * (1 - discount), ['total', 'discount']),

flowWatch(element, key, callback)

Register a watcher from a child element. The event bubbles up until it finds a FlowState source instance that owns key. The returned unsubscribe function removes the watcher again, which is useful in disconnectedCallback() when the element is removed from the DOM. 

// Inside a child element's connectedCallback:
this.#itemsUnsub = flowWatch(this, 'items', items => {
  this.render(items);
});

disconnectedCallback() {
  this.#itemsUnsub();
}

flowGet(element, key)

Synchronously read a value or hook from the nearest ancestor FlowState that owns key. 

const deleteItem = flowGet(this, 'deleteItem'); // retrieve a hook/callback
deleteItem(this.#itemId);

flowThrough(shadowRoot)

Only necessary for state flowing down through a closed shadow boundary, so declarative bindings inside that shadow root receive updates. It is not needed for events flowing up from flowWatch() / flowGet(), because those use composed: true and already cross shadow boundaries automatically. 

connectedCallback() {
  const shadow = this.attachShadow({ mode: 'closed' });
  // Enables downward flow to declarative bindings (flow-watch-*) in this closed shadow
  flowThrough(shadow);
}

Declarative Bindings

FlowState supports declarative DOM bindings via HTML attributes — no JavaScript watcher needed for simple one-way binding. 

<!-- Bind state key 'username' to the element's textContent property -->
<span flow-watch-username-to-prop="textContent"></span>

<!-- Bind to an attribute -->
<img flow-watch-avatar-url-to-attr="src">

<!-- Nested key (dot → dash) -->
<span flow-watch-user-name-to-prop="textContent"></span>

FlowState queries for these attributes inside its scope and updates them automatically when the key changes.

Dots in key names become dashes in attribute names: user.name → flow-watch-user-name-to-prop
Descendants only. Declarative bindings on the root element itself are ignored. Use flowWatch() to reactively bind the root's properties/attributes, or flowGet() to set initial values.

Conditional rendering — flow-if

Use flow-if on a <template>. The template's first element child is the pass case and the second element child (if present) is the fail case. 

<template flow-if="isLoggedIn">
  <section class="welcome">Welcome back!</section>
  <section class="signin">Please sign in.</section>
</template>

The pass/fail branches can be any element tags. If the fail branch is omitted, nothing is rendered when the condition is falsy. 

<!-- Pass-only form -->
<template flow-if="showBanner">
  <aside class="banner">System maintenance tonight.</aside>
</template>

Real app patterns

A common pattern is deriving a boolean from computed data, then using that boolean for flow-if. 


source = {
  filteredTransactions: flowCompute((transactions, filter, sort) => {
    return next;
  }, ['transactions', 'filter', 'sort']),

  showEmptyMessage: flowCompute(
    (filteredTransactions) => filteredTransactions.length === 0,
    ['filteredTransactions']
  ),
};

// Template
<template flow-if="showEmptyMessage">
  <p>No transactions to show.</p>
</template>

source = {
  history: [],
  hasHistory: flowCompute((history) => history.length > 0, ['history']),
};

<template flow-if="hasHistory">
  <section>...recent list...</section>
  <section>No recently viewed items yet.</section>
</template>

Render a list — flow-list

Place flow-list="key" on a container with a <template> child. When the array state key updates, FlowState re-renders the container by cloning the template once per item. Inside the template, bind item fields with flow-<key>-to-prop and flow-<key>-to-attr, where <key> is the field name from the item object: 

<div flow-list="users">
  <template>
    <div flow-id-to-attr="data-user-id">
      <span flow-name-to-prop="textContent"></span>
      <span flow-role-to-prop="textContent"></span>
    </div>
  </template>
</div>

The item key is encoded in the attribute name itself, consistent with flow-watch-*-to-prop scope bindings. Use dashes to access nested properties: flow-user-city-to-prop reads item.user.city.

Timing note: If a flowWatch() watcher on the same array key also updates visual state (e.g. adding a .selected class), wrap that update in queueMicrotask() to defer it until after flow-list has re-rendered the DOM.

Actions

Actions are callbacks or values passed down from parent to child via the state scope. Children read them with flowGet().

Top-level functions in the config are actions. 

// Parent
source = {
  cards: [],
  deleteCard: (id) => this.#deleteCard(id), // top-level function → action
};

#deleteCard(id) {
  this.source.update(({ cards }) => ({
    cards: cards.filter(card => card.id !== id),
  }));
}

// Child (in connectedCallback)
const deleteCard = flowGet(this, 'deleteCard');

Actions are not reactive — flowWatch(el, 'deleteCard', cb) calls cb once with the action value and never again. Use them for stable callbacks and config, not changing data.

Guides

Common Patterns

Parent → Children data flow

The canonical pattern. Parent owns state. Children watch it.

class Child extends HTMLElement {
  #itemsUnsub = () => {};

  connectedCallback() {
    this.#itemsUnsub = flowWatch(this, 'items', items => this.#render(items));
    const remove = flowGet(this, 'removeItem');
    this.#btn.addEventListener('click', () => remove(this.#id));
  }

  disconnectedCallback() {
    this.#itemsUnsub();
  }
}

// parent.js
source = {
  items: [],
  removeItem: (id) => this.#remove(id), // top-level function → action
};

The demo below shows this pattern in action. A work-space root owns workItems and selectedWorkItem state, and exposes selectWorkItem and saveWorkItem actions. The sidebar uses flowWatch and flowGet to connect to the shared scope, while managing its own filter state locally with a nested FlowState source instance.

Component-local state

Each component can have its own FlowState scope for state that shouldn't leak to ancestors or siblings. 

class KanbanColumn extends FlowStateComponent {
  source = {
    selectedCardId: null, // local only
  };
}

Functional updates for dependent state

Always use the functional form when the new value depends on the old one.

// ✓ Safe — prev is a snapshot at flush time
source.update(prev => ({ count: prev.count + 1 }));

// ✗ Risky if called multiple times before flush
source.update({ count: flowGet(root, 'count') + 1 });

Cleanup on permanent unmount

FlowStateComponent already cleans up owned watchers and destroys its source in disconnectedCallback(). If you override it, preserve that behavior. 

class TaskPanel extends FlowStateComponent {
  disconnectedCallback() {
    super.disconnectedCallback();
  }
}

Timing Rules

These are the most common source of bugs.

1. Create FlowSource BEFORE appending children

FlowState registers event listeners on the root. When a child element's connectedCallback fires, it immediately dispatches flow-state-watch and flow-state-get events. If FlowState isn't set up yet, those events have no listener and are silently lost. 

// ✓ Correct
this.#source = new FlowSource(this, config);
flowThrough(shadow);
shadow.appendChild(template.content.cloneNode(true)); // children init here

// ✗ Wrong — children connect before FlowState exists
shadow.appendChild(template.content.cloneNode(true));
this.#source = new FlowSource(this, config);

FlowStateComponent handles this automatically in connectedCallback.

2. Functional API only in connectedCallback

flowWatch() and flowGet() dispatch events that bubble up to a parent FlowState source instance. That source instance only exists once the parent is connected to the DOM. Never call them in a constructor. 

// ✗ Wrong — parent not yet connected
constructor() {
  super();
  flowWatch(this, 'items', cb); // no listener exists yet
}

// ✓ Correct
class Child extends HTMLElement {
  #itemsUnsub = () => {};

  connectedCallback() {
    this.#itemsUnsub = flowWatch(this, 'items', cb);
  }

  disconnectedCallback() {
    this.#itemsUnsub();
  }
}

3. Await update before reading new state

source.update() is batched via microtask — flowGet() immediately after returns the old value. 

// ✓ Read in a watcher (fires after flush)
class CounterView extends HTMLElement {
  #countUnsub = () => {};

  connectedCallback() {
    this.#countUnsub = flowWatch(this, 'count', n => console.log(n));
  }

  disconnectedCallback() {
    this.#countUnsub();
  }
}

// ✓ Await the update
await source.update({ count: 99 });
console.log(flowGet(this, 'count')); // 99

// ✗ Race condition
source.update({ count: 99 });
console.log(flowGet(this, 'count')); // still old value!

4. Initial notification is deferred one microtask

After new FlowSource(root, config), the initial watcher notification is deferred with Promise.resolve().then(…) to give children time to register their watchers. Watchers registered synchronously after construction receive the initial value; watchers registered in a later macrotask may miss it.

Scope & Shadow DOM

FlowState uses DOM event bubbling to locate the right scope. Shadow DOM normally blocks bubbling — FlowState handles this by dispatching events with composed: true, which crosses shadow boundaries. The flowThrough() call links a shadow root into a parent's scope for declarative bindings; it's not required for the functional API (flowWatch/flowGet) because those events are already composed. 

document
 └─ <my-app>              ← FlowState scope (root = my-app)
     └─ #shadow-root      ← flowThrough() links this in
         └─ <my-column>   ← FlowState scope (root = my-column)
             └─ #shadow-root
                 └─ <my-card>   ← watch/get bubble up through shadows

When <my-card> calls flowWatch(this, 'theme', cb):

  1. Event bubbles through my-column's shadow → host → my-app's shadow → host
  2. If my-column owns theme, it intercepts and stops propagation
  3. If not, my-app intercepts it
  4. The first ancestor that has the key wins

Devtools

flowDevtools();

Call this once, early in your app entry point. It opens the devtools panel in a new tab and connects via BroadcastChannel. The devtools show all active FlowState scopes, their current state values, watchers, and the source element that registered each watcher. Clicking a watcher in the panel highlights the corresponding element in the app.
